## Section: Built on tools you already use

TanStack Start for the site, Supabase for the database and sign-in, Vercel for hosting. Every client gets their own repository, database, and deployment, so nothing is shared between projects.

## Section: Sign-in that's secure by default

Email and password, optional Google sign-in, and password reset are ready to go. Sessions are kept in secure cookies and checked on the server. Turn on authenticator apps for admins only, or for everyone, from the settings screen.

**Link:** Authentication and MFA (`/docs/auth-and-mfa`)

## Section: Roles checked twice

Every new account is a member. Admins manage content, media, settings, and people. Permissions are checked by the app and again by the database on every request.

**Link:** Roles and permissions (`/docs/roles`)

## Section: An admin panel your client can use

Edit pages and blog posts in a block editor, manage images, set up redirects, invite people, and change branding without touching code.

**Link:** Admin panel (`/docs/admin-panel`)

## Section: Blog, search, and contact

A blog with an RSS feed, full-text search across published pages and posts, and a contact form with spam protection. No extra services to sign up for.

**Links:** Blog (`/docs/blog`), Search (`/docs/search`), Contact form (`/docs/contact`)

## Section: Schema changes you can see

The SQL templates screen lists every migration with a plain-English summary and shows which ones your database has applied. It never runs SQL itself.

**Link:** SQL templates (`/docs/sql-templates`)

## Section: An API and MCP server

Read and update content, posts, settings, and users over REST, or connect an AI assistant through MCP. Tokens carry only the scopes you pick, expire on a date you set, and can't do more than you can. Changes need a confirmation and can't be applied twice by accident.

**Link:** API and MCP (`/features/api-and-mcp`)
